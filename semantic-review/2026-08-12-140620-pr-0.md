# Composite Review turn closes core recovery gaps but still permits primitive Host takeover

This follow-up now carries cumulative Candidate paths into both Reviewer callback paths, reconciles a committed claim after its response is lost, preserves the composite Host owner across a pause, embeds canonical pause results, and reshapes the opt-in installed-package test around the packaged two-tool workflow. The durable claim path uses the real five-minute lease, and the packaged workflow no longer calls primitive `smartflow_result` when the user gives no answer. Two **confirmed P1 blockers** remain: compatibility primitives can bypass an active composite Host owner and disclose the worktree, while generic revision pauses advertise an approval whose template is not a valid complete answer. **Watch for:** **confirmed P1 blocker** primitive `resume → claim_action` Host takeover; **confirmed P1 blocker** action-only generic approval templates; **confirmed P2** inspection-answer and repair-budget primitive asymmetries; **confirmed residual evidence gap, non-blocking to code review** unexecuted real Pi and absent transcript.

**Verdict**: NEEDS_CHANGES

## High-level view

Original P1s (1) and (2) are closed. `changedPaths` reaches both composite and legacy Reviewer callbacks, while claim failures reread durable state, reconcile a committed five-minute claim, and schedule from that lease instead of the thirty-minute Host deadline.

The composite `PAUSED → AWAITING_USER_INPUT` path retains the old owner and validates the old token during persistence. A **confirmed P1** remains across API surfaces: `smartflow_resume` and `smartflow_claim_action` do not enforce `run.hostTurn`, so another Host can reopen the paused Review and receive its worktree.

`USER_INPUT_REQUIRED` now carries canonical `ResultOutput`, separates inspection entries, and supports no-answer return without a primitive result call. A **confirmed P1** remains for generic source-drift and Worker pauses: their action-only revision template cannot pass the complete approval-answer schema. Two **confirmed P2** contract asymmetries also remain because inspection actions parse as answers but are rejected at runtime, and primitive `resume_review_decision` does not reset the durable repair budget.

The installed-package test now imports packaged `executeApprovedWorkflow`, enforces `execute → review_turn*`, forces a dynamic-marker repair, observes Revision 2+, and verifies Reviewer `CREATE → RESUME` before Publish. Its real-Pi gate remains explicit. The unexecuted model path and missing checked-in transcript are a **confirmed residual evidence gap**, not a demonstrated code failure.
