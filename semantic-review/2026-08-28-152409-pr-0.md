## Latest-only 对象契约保留证据绑定

TaskManifest 与 durable Review/Leader 仍使用 strict schema，Candidate verifier 仍执行 exact-key 与 `candidateHash` 重算；snapshot 则按计划保留原有字段值、entry 与 logical hash 校验，不新增旧 payload 专用 strict-schema 分支。Publish 前仍重验 Candidate、Review 和 Leader semantic hash、Review history 与 accept gate，再以 `projectId`、`jobId`、`candidateHash`、`reviewHash` 和 `operationsHash` 建立稳定 operation ID。

## SQLite schema 5 形成断代门槛

`withDatabase()` 在执行当前 DDL 前只接受 `PRAGMA user_version` 0 或 5，因此 layout 4 不会被误当成新布局。`project_state` 的 DDL、row mapping、insert/update 和 crash writer 已统一为五列；测试覆盖 fresh schema 的版本与列集合，以及 layout 4 fail-closed 且不改写版本的行为。
