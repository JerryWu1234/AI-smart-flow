# Daemon-owned review turns with durable Host checkpoints

This change adds `smartflow_review_turn` as a composite daemon API that owns polling, Review claims and renewals, automatic Leader decisions, repair approval, repair-round accounting, and publish progression while leaving Reviewer execution in the Host. It persists `hostTurn` and `autoRepairRounds` in schema v4 and wraps the original ten MCP mutations with deterministic child request IDs. The production E2E covers the happy repair, restart, renewal, limit-reset, and publish path. **Watch for:** **confirmed P1** stale tokens can become a fresh claim and disclose its worktree; **confirmed P1** renewal/deadline timers can be lost on restart or one failed renewal; **confirmed P1** a crashed `CLAIMING` checkpoint has no expiry/recovery path; **confirmed P1** project-wide state-version races escape the composite API; **confirmed P1** USER revision approval cannot be constructed from `USER_INPUT_REQUIRED`; and **confirmed P2** invalid-review pauses are conflated with the repair limit and offer a no-op retry.

**Verdict**: NEEDS_CHANGES

## High-level view

The coordinator layers a durable state machine over the existing lifecycle mutations. `CLAIMING`, `AWAITING_REVIEW`, and `AWAITING_USER_INPUT` record the Host boundary, while deterministic child IDs make the main successful transitions replayable.

Only `REVIEW_REQUIRED` is modeled with an absolute worktree path, and the lower Review coordinator still enforces claim, task/Candidate, attempt, and Reviewer-session bindings. A **confirmed P1** stale-token flaw bypasses that boundary by treating an obsolete submission as a new poll, which can create or reveal a later Review claim.

A **confirmed P1** lifecycle flaw leaves claim liveness on one in-memory 60-second timer. Recovery ignores the remaining five-minute lease, repeated calls postpone renewal, and one suppressed renewal error also disables the 30-minute deadline wake-up; a separate **confirmed P1** gap leaves the durable `CLAIMING` stage unrecovered and unexpired.

A **confirmed P1** concurrency flaw still exposes global project `stateVersion` races. Progress on another run can advance the version between a composite status/read and its child mutation, and the coordinator does not reconcile the expected conflict.

A **confirmed P1** contract gap affects revision approval: USER approval needs a task path, source hash, and approval object, but `USER_INPUT_REQUIRED` exposes only an action string and the host-skill helper handles only repair-limit continuation.

Automatic accept, incomplete-task repair, durable round counting, and the fifteen-round reset are centralized. A **confirmed P2** cause-mapping flaw discards whether a pause came from the limit or an invalid Review, mislabels some pauses, and can reevaluate the same non-actionable Review forever.

1. **Stale-token worktree disclosure** (**confirmed**, P1) — A stale Review, failure, or answer token is fed back into normal advancement and can claim or reveal a later worktree. Return a non-sensitive stale response without advancing or changing ownership.
2. **Lossy renewal/deadline timer** (**confirmed**, P1) — Restart near lease expiry, frequent turn calls, or one renewal error can stop claim renewal and the 30-minute deadline check. Schedule from durable lease/deadline timestamps and retry or durably pause on failure.

<details><summary>Details</summary>

## Stale turn tokens can acquire the next Review worktree — P1, confirmed

All three continuation handlers turn a missing or mismatched token into `advance`: Review submission at `apps/daemon/src/host-turn-coordinator.ts:440-447`, unavailability at `apps/daemon/src/host-turn-coordinator.ts:491-504`, and user answers at `apps/daemon/src/host-turn-coordinator.ts:658-667`. `advance` can claim `REVIEW_PENDING` work at `apps/daemon/src/host-turn-coordinator.ts:250-251` or return the current Review at `apps/daemon/src/host-turn-coordinator.ts:253-267`; both reach the absolute path emitted at `apps/daemon/src/host-turn-coordinator.ts:418-428`.

An old submission arriving after a new revision can discard its payload, bind the new turn to the stale caller's `hostTurnId`, and return the new worktree. If another Host already owns the turn, this supposedly soft path throws `HOST_TURN_OWNED_BY_ANOTHER_HOST`. Return a dedicated stale response, or a non-sensitive `NOT_READY` snapshot, directly from the mismatch branches; it must not call `advance`, mutate ownership, or return `REVIEW_REQUIRED`.

## Renewal and deadline enforcement share a lossy timer — P1, confirmed

Recovery schedules a fixed delay only for unexpired `AWAITING_REVIEW` turns at `apps/daemon/src/host-turn-coordinator.ts:195-200`; it does not inspect durable `pendingAction.claimExpiresAt`. A restart with less than sixty seconds on the five-minute claim lease waits a full minute before renewing. Returning an existing Review also clears and recreates the timer (`apps/daemon/src/host-turn-coordinator.ts:265-267`, `308-312`, and `730-743`), so calls more frequent than once per minute can postpone renewal until expiry.

The callback removes itself and suppresses every error at `apps/daemon/src/host-turn-coordinator.ts:735-739`; only success schedules another callback at `apps/daemon/src/host-turn-coordinator.ts:751-776`. One CAS conflict, store error, or expired lease therefore ends renewal. The 30-minute check runs only through the same callback at `apps/daemon/src/host-turn-coordinator.ts:758-761`, so it stops too. Schedule against the earliest of the 60-second cadence, a safety margin before `claimExpiresAt`, and `deadlineAt`; preserve an earlier timer, retry recoverable failures, and durably report Host unavailability when the lease cannot be retained.

## `CLAIMING` can remain owner-locked past its durable deadline — P1, confirmed

Recovery ignores `CLAIMING` at `apps/daemon/src/host-turn-coordinator.ts:195-200`. A crash between intent persistence and the lower claim leaves `REVIEW_PENDING` with a Host owner and no timer. A later call rejects every other Host at `apps/daemon/src/host-turn-coordinator.ts:313-314`, preserves the old deadline at `apps/daemon/src/host-turn-coordinator.ts:319-328`, and claims without first checking expiry at `apps/daemon/src/host-turn-coordinator.ts:329-351`.

Recover both legal combinations: replay the claim for `REVIEW_PENDING`, and reconcile the lower claim for `REVIEWING`. Enforce `deadlineAt` before either path; clear or durably pause an expired pre-claim intent so it cannot lock the run indefinitely.

## Project-wide CAS races leak out of the composite API — P1, confirmed

`advance` passes a status version into later repair approval, user-input persistence, and claim intent at `apps/daemon/src/host-turn-coordinator.ts:229-251`. The claim path rereads state but still gives `persistHostTurn` the earlier version at `apps/daemon/src/host-turn-coordinator.ts:303-337`. Review submission, unavailability, answers, renewal, and deadline expiry each read once and mutate later at `apps/daemon/src/host-turn-coordinator.ts:439-485`, `490-523`, `657-689`, and `751-800`. The decision expression at `apps/daemon/src/host-turn-coordinator.ts:548-564` selects the latest read version but can still race before mutation.

Because `stateVersion` belongs to the project, progress on another active task can invalidate each window. The per-run queue does not serialize that other run, and no `STATE_VERSION_MISMATCH` handler reruns the composite state machine. Add a bounded CAS/reconciliation loop that rereads state, recognizes already-committed deterministic children, and retries only expected stale-version conflicts with stable child IDs.

## USER repair approval is not representable from the turn response — P1, confirmed

The input accepts `tasksPath`, `approvedSourceHash`, and `approval` in a structured answer at `packages/protocol/src/schema/mcp-tools.ts:370-380`. The output exposes only `{ answer: string, description: string }` at `packages/protocol/src/schema/mcp-tools.ts:450-465`, and the coordinator omits the durable repair draft at `apps/daemon/src/host-turn-coordinator.ts:628-652`. That string cannot satisfy the legacy runtime's USER requirements at `apps/daemon/src/project-runtime.ts:877-905` without an out-of-band `smartflow_result` call, contradicting the documented turn-only flow.

`executeApprovedWorkflow` compounds the gap: it maps only `AUTOMATIC_REPAIR_LIMIT` to `resume_review_decision` and returns `smartflow_result` for every other user prompt at `apps/host-skill/src/workflow.ts:66-94`. Include `repairDraft` plus a typed answer template or required-input descriptor in `USER_INPUT_REQUIRED`, and add a generic callback returning validated `ReviewTurnInput["answer"]` for USER approval, cancel, and retry.

## Invalid Review pauses lose their cause and offer a no-op continuation — P2, confirmed

`planReviewDecision` distinguishes no actionable findings from the limit, but checks the limit with exact equality at `packages/review/src/review-decision.ts:47-63`. Both plans become legacy `LEADER_PAUSED` at `apps/daemon/src/host-turn-coordinator.ts:555-572`, then `requireUserInput` reconstructs the public cause solely from `autoRepairRounds >= 15` at `apps/daemon/src/host-turn-coordinator.ts:589-600`. An invalid Review at round fifteen is mislabeled `AUTOMATIC_REPAIR_LIMIT`, while a counter above fifteen permits another automatic repair.

Below the limit, `resume_review_decision` resets the counter and reevaluates the same durable invalid Review, returning to the same pause. Persist the plan's exact cause, use `>= REPAIR_ROUND_LIMIT`, and expose `resume_review_decision` only for a real limit pause. Invalid Review needs a new bound Review attempt or only a cancel option.

## Coordinator edge cases are absent from the test boundary — P2, confirmed

The production test at `tests/e2e/production-repair-loop.test.ts:690-918` covers immediate restart, one successful renewal, manual deadline expiry, retry, a seeded count of fifteen, reset, repair, and publish. The protocol test only proves that non-Review variants reject a syntactically supplied worktree path. No direct `HostTurnCoordinator` test covers stale tokens, child replay/CAS conflicts, renewal rejection, near-expiry recovery, `CLAIMING` recovery, USER approval, or invalid-review continuation.

Add coordinator tests with fake dependencies and timers for each crash and mutation boundary. Assert that stale tokens never return paths or acquire ownership, timer exits reschedule or durably transition, old schema-v4 records without the optional fields load, and all ten legacy handlers remain independently callable.
