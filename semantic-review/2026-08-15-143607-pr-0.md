# SQLite StateStore authority, mutation leases, and durable publish evidence

This change moves Project state and audit history from `state.json`/`events.jsonl` to WAL-mode SQLite, replaces the Project mutation file lock with a database lease plus `stateVersion` CAS, and retires legacy files into protected content-addressed archives. The earlier live-socket cleanup bug, first-import archive races, and Worker exposure of the current retired archives are addressed. The lease remains owned through effect invocation, but its local-owner identity is only hostname plus PID, so a dead owner whose PID is reused cannot recover automatically. Candidate v3 and the signed DeliveryBundle preserve publish/recovery evidence after temporary Git state is removed.

**Watch for:** **confirmed** — PID reuse can strand an expired lease owned by a dead process; **confirmed** — every hot `readState()` re-hashes retained legacy archives; **confirmed** — retirement coverage uses many instances but not independent processes or a real sandbox denial; **confirmed** — calling `LocalIpcServer.start()` twice can unlink the live endpoint and orphan the first listener.

**Verdict**: NEEDS_CHANGES

## High-level view

The mutation lease serializes builders across StateStore instances, checks ownership in the same SQLite transaction as each state write, and remains held across commit, effect preparation, and effect invocation. Receipts are reread after lease acquisition, while project and Run fences reject stale callbacks; the remaining blocker is that PID alone is not a durable process identity across reboot or PID reuse.

Legacy import commits the state row, event rows, and source hashes before filesystem retirement. Concurrent callers converge on verified hash-named files under `legacy-imports/`, later unregistered state fails closed, later `events.jsonl` is ignored, and the archive directory is covered by Worker deny rules; however, every state read reopens and hashes the immutable archives again.

Daemon startup now acquires the installation singleton before migration or recovery and only removes an endpoint that the same server instance bound. A repeated `start()` on the same object still reuses its lock, unlinks its own endpoint, and overwrites the tracked listener.

Candidate v3 binds the three snapshot hashes and cumulative operations without duplicate patch evidence. Publish freezes a derived patch, operations, and blobs into the signed DeliveryBundle before apply, and recovery validates and reads that bundle without the worktree; the changed specs consistently describe this lifecycle and SQLite/events authority.

<details><summary>Details</summary>

## Lease handoff survives expiry but not process-instance reuse

**S1 blocker / confirmed.** `mutation_lease` persists `owner_pid` and `owner_hostname`, but no boot ID or process start token (`packages/state-store/src/state-store.ts:52-58`). For an expired local row, stale removal calls `process.kill(pid, 0)` and keeps the row whenever any process currently has that PID (`packages/state-store/src/state-store.ts:459-477`). After a crash or reboot, PID reuse makes every contender skip deletion regardless of `expires_at_ms`, wait five seconds, and return `PROJECT_LOCKED`.

```text
old owner(pid 421) dies ── lease row remains expired
OS assigns pid 421 to a new process
contender: kill(421, 0) succeeds ──> stale row is never deleted
```

The commit-to-effect-start path holds the lease through `prepareEffect`, ownership assertion, and effect invocation (`apps/daemon/src/project-mutation-executor.ts:260-275`). Persist and compare a process-instance token that changes across PID reuse/reboot. Cover an expired row with the current PID but a mismatched start token, plus a killed owner with a matching token.

## Legacy retirement re-verifies unbounded archives on every read

**S2 residual / confirmed.** Reconciliation runs whenever an existing SQLite row is read (`packages/state-store/src/state-store.ts:754-757`). `ensureProtectedLegacyArchive()` reads and hashes the entire archive, then `verifyLegacyArchive()` reads and hashes it again (`packages/state-store/src/state-store.ts:969-993`), for both state and imported events. A large historical `events.jsonl` makes every status check and mutation perform O(archive size) I/O and allocation. Verify retirement once at migration/startup or record/cache a reconciled archive identity, while retaining an integrity check at the recovery boundary.

## Process and sandbox boundaries remain absent from retirement coverage

**S3 residual / confirmed.** The concurrency regression creates 50 `StateStore` objects and runs them through one Node process (`tests/crash/atomic-state.test.ts:353-355`). It does not cover process scheduling, process death between rename and tombstone, or raw filesystem errors crossing child boundaries. It also checks that `protectedPaths` contains `legacy-imports/` rather than launching the Worker sandbox and proving descendants are unreadable.

Add child-process fan-out over one first-time import, require the same state or a typed StateStore error with no raw `ENOENT`, and validate final marker/archive hashes. Attempt to read retired state and events archives through the actual sandbox profile.

## Repeated LocalIpcServer start can replace its own endpoint

**S3 residual / confirmed.** `acquireInstanceLock()` returns when this object already has a lock (`apps/daemon/src/local-ipc-server.ts:98-104`), while `start()` has no `server`/`endpointOwned` guard and unlinks the Unix pathname before assigning a new listener (`apps/daemon/src/local-ipc-server.ts:107-112`). A second call can leave the first server on an unlinked inode, replace `this.server`, and prevent `close()` from closing the first listener. Production currently starts each object once; reject or idempotently return from repeated/concurrent starts and add a lifecycle test.

## Validation and remaining boundaries

The targeted matrix passed 57/57 tests across WAL crash recovery, lease handoff, state concurrency, daemon startup, publish CAS/recovery, Candidate v3, Worker lifecycle, and terminal cleanup. Root TypeScript checking and `git diff --check main` passed. The local run used Node v25.1.0; the added Node 22.19 CI job was not executable locally. **Not tested (confirmed):** true multi-process retirement fan-out, PID-reuse recovery, and actual sandbox denial of archived bytes.
