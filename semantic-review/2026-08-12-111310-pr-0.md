# Daemon-owned Review turn lacks safe Host handoff and real end-to-end closure

This change adds the four-state `smartflow_review_turn` API, durable Host-turn checkpoints, daemon-owned claim/renew/decision/repair mechanics, an eleven-tool MCP surface, and a two-tool Host workflow. The schema/registration path is connected, and the installed Pi 0.83.0 loader accepts the bundled Extension's `registerProvider` call, but five **confirmed P1** gaps remain at the behavioral boundaries. The Host callback loses cumulative paths, a lost claim response misses the five-minute lease wake, paused turns can transfer ownership, several pauses cannot be resolved from the composite response, and no test traverses the new MCP tool with real Pi and the packaged Host workflow. **Watch for:** **confirmed P1** incomplete Reviewer context; **confirmed P1** post-claim `CLAIMING` lease loss; **confirmed P1** paused-turn Host takeover; **confirmed P1** non-self-contained `USER_INPUT_REQUIRED`; **confirmed P1** missing real two-tool E2E.

**Verdict**: NEEDS_CHANGES

## High-level view

The protocol returns cumulative `changedPaths`, but the new high-level Host workflow drops that field while constructing the Reviewer callback context. This **confirmed P1** prevents the Reviewer from enumerating the Candidate scope and breaks the opt-in installed fixture's callback contract.

The durable `CLAIMING` state recovers after daemon restart, but the live lost-response path still schedules from the pre-claim snapshot. This **confirmed P1** leaves a successfully acquired five-minute lease unattended until the thirty-minute review deadline unless the Host retries.

Host ownership is checked while claiming or awaiting Review, but the transition into `AWAITING_USER_INPUT` bypasses token and owner checks. This **confirmed P1** lets a second Host take over an unavailable-Review pause and reacquire the worktree.

`USER_INPUT_REQUIRED` handles repair-draft approval and repair-limit continuation, but not all durable pauses. This **confirmed P1** exposes revision-approval options without required fields, removes inspection evidence/actions, and makes the packaged Host workflow fall back to `smartflow_result`.

The new two-tool production test uses a fake Worker and calls `ProjectRuntime` directly; the opt-in installed real-Pi test uses MCP and packaged Host code but follows the old primitive loop. This **confirmed P1** leaves the phase-4 path—new MCP tool, real Pi, Host Skill, CREATE/RESUME, repair, and Publish—unexecuted and unaudited.

## Cumulative Candidate paths disappear before the Reviewer callback — P1, confirmed

`REVIEW_REQUIRED` carries `changedPaths` in `packages/protocol/src/schema/mcp-tools.ts:430`, and the coordinator populates it at `apps/daemon/src/host-turn-coordinator.ts:580`. The new Host workflow creates `ReviewActionContext` at `apps/host-skill/src/workflow.ts:107-115` without copying `turn.changedPaths`; the callback type at `apps/host-skill/src/reviewer.ts:13-20` has no such field. The legacy callback construction repeats the omission at `apps/host-skill/src/action-loop.ts:269-277`.

Reproduce with an Action reporting `changedPaths: ["src/a.ts", "src/b.ts"]`, then run `executeApprovedWorkflow` with a callback that iterates `context.changedPaths`. Expected: both paths reach the callback so it can inspect every cumulative change. Actual: the field is `undefined`; iteration fails three times and the workflow reports Host-review-unavailable. The installed fixture performs this iteration at `tests/fixtures/installed-mcp-lifecycle-child.mjs:146-160`, so an authorized run cannot currently submit Review.

The Host tests put `changedPaths` in fake responses at `apps/host-skill/src/workflow.test.ts:134,218` but only assert `reviewerSession.mode` at `:252-254`. The production E2E hard-codes `pathCoverage` and `combineReviewStageResults(["sum.js"], ...)` at `tests/e2e/production-repair-loop.test.ts:242-259`; the only fixture consuming callback paths is skipped by default.

## A successful claim with a lost response is not woken before lease expiry — P1, confirmed

The coordinator persists `CLAIMING` and schedules from the pre-claim state at `apps/daemon/src/host-turn-coordinator.ts:427-436`. It awaits the claim at `:440-468`, then installs a lease-aware wake only after the promise returns at `:468`. If the mutation commits `REVIEWING + claimExpiresAt` and the response is lost, `scheduleClaimingWake` retains the earlier snapshot; its lease branch applies only to a snapshot already in `REVIEWING` at `:1078-1096`.

Production claims expire after five minutes (`apps/daemon/src/review-coordinator.ts:196`), while the Host deadline is thirty minutes (`apps/daemon/src/host-turn-coordinator.ts:41,423-425`). Reproduce by committing the normal claim state inside `dependencies.claim`, then throwing a transport error without restart or another Host poll. Expected: reconcile after one second or no later than thirty seconds before lease expiry, returning the same `REVIEW_REQUIRED`. Actual: no wake until minute thirty; the lease expires at minute five and the eventual wake can only pause the Review.

The lost-response test sets `claimExpiresAt` to `10:35` at `apps/daemon/src/host-turn-coordinator.test.ts:551`, later than the coordinator's `10:30` deadline, so it proves deadline-pause retry rather than the production lease-first ordering. The post-claim test calls `recoverRun`, whose fresh read repairs the timer, and does not cover a live process after the claim call throws.

## A paused Review can be stolen by another Host — P1, confirmed

`ReviewCoordinator.pauseForHostUnavailable` spreads the existing Run and retains its Host turn at `apps/daemon/src/review-coordinator.ts:527-543`. `requireUserInput` checks ownership only when the checkpoint is already `AWAITING_USER_INPUT` (`apps/daemon/src/host-turn-coordinator.ts:769-772`); otherwise it creates a new turn from the caller's `hostTurnId` at `:779-786`. `persistHostTurn` then disables token and owner mismatch checks for this Review-to-user-input replacement at `:925-941`.

Reproduce with Host A obtaining `REVIEW_REQUIRED`, then force deadline or renewal failure so the Run becomes `PAUSED/HOST_REVIEW_UNAVAILABLE` while retaining A's `AWAITING_REVIEW`. Host B polls without a token, receives `USER_INPUT_REQUIRED`, answers `retry_host_review`, and reaches a newly claimed `REVIEW_REQUIRED` worktree. Expected: `HOST_TURN_OWNED_BY_ANOTHER_HOST` until A explicitly relinquishes ownership. Actual: B gains mutation authority and path access.

Stale-continuation tests cover a mismatched token, and recovery tests reuse `host-1`; none polls a paused A-owned Review as Host B. The owner-bypass branch is untested.

## `USER_INPUT_REQUIRED` is not sufficient for every durable pause — P1, confirmed

A structured revision template is emitted only when `result.repairDraft` exists with USER approval (`apps/daemon/src/host-turn-coordinator.ts:821-850`). Other pauses advertise `approve_new_manifest_revision`, including Worker `BLOCKED` at `apps/daemon/src/worker-runner.ts:659` and approved-source drift at `apps/daemon/src/runtime-composition.ts:319-321`. Their response contains only the string option; submitting it is rejected for missing approval and `tasksPath + approvedSourceHash` at `apps/daemon/src/project-runtime.ts:902-928`.

`PUBLISH_CONFLICT` and containment reconciliation expose `inspect_conflict` or `inspect_processes` at `apps/daemon/src/recovery-manager.ts:387` and `apps/daemon/src/worker-runner.ts:806-815`, but `READ_ONLY_RESUME_ACTIONS` removes them at `apps/daemon/src/host-turn-coordinator.ts:45-54,158-163`. The coordinator reads the canonical result but omits `publishPrecheck` and inspection evidence. Expected: the composite response supplies all fields/evidence for each legal intervention, or does not advertise an unusable action. Actual: the Host must cancel blindly or call a primitive; `executeApprovedWorkflow` calls `smartflow_result` at `apps/host-skill/src/workflow.ts:101-105`.

Tests cover only a repair draft already carrying a complete USER template (`apps/daemon/src/host-turn-coordinator.test.ts:710-784`; `apps/host-skill/src/workflow.test.ts:317-423`). They omit generic Worker block, source drift without a repair draft, publish conflict, containment pause, and the primitive fallback.

## No E2E traverses new MCP, real Pi, Host Skill, repair, and Publish together — P1, confirmed

The production test reaches `smartflow_review_turn`, restart, repair, and Publish, but injects `RepairLoopProvider` at `tests/e2e/production-repair-loop.test.ts:59-139` and sends tool names directly to `ProjectRuntime.handle` through `RuntimeGateway` at `:142-157`. It bypasses MCP transport, the real Pi child, and the packaged high-level Host workflow. The installed test is gated by `it.runIf(runRealPiE2e)` at `tests/e2e/installed-package.test.ts:11,129`; its child uses `smartflow_wait/status`, `HostActionLoop.pollOnce`, `smartflow_submit_leader_decision`, and `smartflow_result` at `tests/fixtures/installed-mcp-lifecycle-child.mjs:41-55,137-180,198`, with no `smartflow_review_turn`, automatic repair, or Reviewer `RESUME`.

`pnpm exec vitest run tests/e2e/installed-package.test.ts --no-file-parallelism` reports one skipped test. With the gate enabled, the current callback first fails on missing `context.changedPaths`; after that defect is fixed, the trace still follows old primitives and accepts on the first Review. Expected phase-4 evidence is installed MCP `smartflow_execute → smartflow_review_turn*` using real Pi and packaged Host Skill through CREATE, automatic repair, RESUME of the same Reviewer, and terminal Publish/result. Actual evidence is split across incomplete tests; `.smartflow-e2e` contains generated fixture files but no redacted call/session transcript.

T208/T209 remain open at `specs/001-smartflow-mvp/tasks.md:245-246`, and the local baseline counts the real test as skipped at `:251-253`. The requested real end-to-end merge gate is therefore unmet.
