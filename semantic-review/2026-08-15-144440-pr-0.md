# SQLite StateStore migration with process-bound leases and idempotent daemon startup

This follow-up closes the prior S1 lease-recovery blocker: schema v3 persists a process-start token and expired local leases are retained only when PID and process instance still match. Legacy archive verification is cached after reconciliation while `state.json` remains a checked retirement/dual-authority boundary, and repeated or concurrent IPC starts now converge on one listener. The migration keeps `state.sqlite` as recovery and audit authority, combines a database lease with `stateVersion` CAS, and acquires the daemon singleton before migration or recovery effects. No blocker remains; the prior subprocess-retirement and end-to-end archive-denial coverage gap is still present.

**Watch for:** **confirmed residual** — legacy retirement is still raced only by stores in one process, and Worker archive denial is inferred from wiring plus a generic sandbox test rather than exercised against the retired archives.

**Verdict**: APPROVED

## High-level view

The mutation lease now records `owner_process_start_token` alongside hostname and PID. An expired matching process instance retains ownership, owner death or a mismatched token permits recovery, and an unavailable identity check fails closed.

Legacy files remain one-time bootstrap inputs whose hashes and audit rows commit with SQLite before retirement. Each `StateStore` verifies protected archives once, then checks the small `state.json` tombstone on hot reads so recreated state authority still fails closed without re-hashing historical event bytes.

Daemon startup owns `daemon.lock` before recovery. Concurrent `LocalIpcServer.start()` calls share one startup, and calls after success return without unlinking or replacing the live endpoint.

The Worker receives SQLite, WAL/SHM, legacy source, and archive paths as read denials. The remaining non-blocking gap is that first-import fan-out remains intra-process and the composed Worker/archive denial is not exercised end to end.

## Expired mutation leases distinguish owner death from PID reuse

The v3 schema adds and upgrades `owner_process_start_token`; new leases persist the `/bin/ps` start identity with hostname and PID (`packages/state-store/src/state-store.ts:20,58,115-122,488-509,882-922`). After expiry, a matching token preserves a suspended owner, an unavailable identity returns `PROJECT_LOCKED`, and a mismatch permits token-scoped deletion (`packages/state-store/src/state-store.ts:511-540`). The crash suite covers an expired live child, recovery after that child dies, and a live current PID carrying a different recorded token (`tests/crash/atomic-state.test.ts:274-339`). Cross-process receipt coverage also shows a waiting mutation replays the winner instead of rebuilding stale state (`tests/crash/atomic-state.test.ts:341-379`).

## Legacy authority reconciliation leaves the hot path

Reconciliation caches the imported state/events hash pair only after archive verification. Cache hits still parse `state.json` and require the expected protected tombstone; deletion or replacement invalidates the cache (`packages/state-store/src/state-store.ts:1018-1033`). SQLite commits state, imported audit rows, and source hashes before archive movement and tombstoning, so a later reader can finish a commit-before-rename interruption (`packages/state-store/src/state-store.ts:814-879,1035-1124`). A later `state.json` is rejected as dual authority, while recreated `events.jsonl` is intentionally ignored (`packages/state-store/src/state-store.ts:1072-1142`).

## Daemon ownership and listener startup converge

Production startup acquires the installation lock before `ProjectRuntime.recover()` and disposes the runtime/server on failure (`apps/daemon/src/main.ts:85-105`). Successful starts return immediately and in-flight starts share one promise (`apps/daemon/src/local-ipc-server.ts:95-145`). The integration case starts one object concurrently, repeats start after success, rejects a second server, and confirms the first endpoint still responds (`tests/integration/short-mcp-calls.test.ts:59-84`).

## Archive retirement and sandbox acceptance remain indirect

**S3 residual / confirmed.** The retirement race constructs 50 `StateStore` instances in one Node process and asserts archive hashes plus `protectedPaths` membership (`tests/crash/atomic-state.test.ts:381-423`); it does not cover independent importers or process death during rename/tombstone repair. WorkerRunner passes `StateStore.protectedPaths` into `deniedReadPaths` (`apps/daemon/src/worker-runner.ts:213-220,987-1013`), and the Darwin adapter denies a caller-supplied generic file (`tests/security/pi-containment.test.ts:22-81`), but no acceptance case attempts to read the actual SQLite files or retired archives through WorkerRunner.

SQLite transaction/CAS behavior has real cross-process coverage and the deny adapter is independently exercised, so this is a residual test gap rather than a shipping blocker. Add child-process first-import fan-out with a commit-to-retirement crash, then use the real Worker path to assert denials for `state.sqlite` and both hash-named archives.
