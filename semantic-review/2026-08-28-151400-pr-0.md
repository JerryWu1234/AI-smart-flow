# 应用层 `schemaVersion` latest-only 断代

本变更从 ProjectState、TaskManifest、Git snapshot、Candidate、durable Review/Leader decision 和 Doctor JSON 中移除固定格式版本，同时保留真正控制 mutation、恢复和发布的运行身份与完整性校验。SQLite 物理布局由 4 升至 5，删除文档版本镜像，并明确不提供 migration。Candidate 直接成为公共 interface，manifest/Candidate/Review/Leader identity 均由无版本 payload 自然重算，publish operation ID 的输入未变。实现链路未发现代码级故障，但旧 SQLite 布局拒绝缺少回归测试，且一份现行设计文档仍宣称 ProjectState 使用 v7。

Watch for: **confirmed（P2）** 没有测试覆盖 SQLite `user_version = 4` 或其他非 0/5 布局的拒绝；**confirmed（P2）** `docs/plans/daemon-driven-review.md` 仍把当前状态描述为 `schemaVersion: 7`。

**Verdict**: NEEDS_CHANGES

## High-level view

应用对象已经收敛为单一无版本 shape。Producer、strict parser、Candidate exact-key verifier 和 Review/Leader semantic hash 都使用同一 payload；Recovery 继续绑定 task source、manifest ArtifactRef SHA、snapshot、Candidate、Review/Leader、attempt generation 和 publish CAS，没有引入 dual-read、fallback 或 legacy alias。

SQLite 采用硬断代：新数据库创建 layout 5 和五列 `project_state`，运行时以 `STATE_MIGRATION_UNSUPPORTED` 拒绝所有非 0/5 版本。测试目前只验证新库布局，未保护拒绝旧布局这一半契约，这是 **confirmed（P2）** 覆盖缺口。

Publish identity 仍只包含 `projectId`、`jobId`、`candidateHash`、`reviewHash` 和 `operationsHash`；`decisionHash` 只作为发布前证据校验，不进入 operation ID。Recovery fixture、生命周期测试和 fresh build 已覆盖新 payload 哈希链及构建产物。

新增 changeset 已声明 latest-only breaking cutover 与清理 Data Directory 要求，但 daemon-driven Review 计划仍使用当前 v7 的表述，形成 **confirmed（P2）** 的升级契约冲突。

## 无版本 artifact 仍组成单一证据链

本次不是增加第二套 reader，而是在每个 producer/verifier 同步删除固定字段：

```text
TaskManifest bytes -> manifest ArtifactRef SHA
RUN_BASELINE + RUN_RESULT -> Candidate body -> candidateHash
candidateHash + review body -> reviewHash
reviewHash + leader body -> decisionHash -> leader artifact path
candidateHash + reviewHash + operationsHash -> publish operation ID
```

`packages/workspace/src/candidate-builder.ts:20-78` 直接定义 `Candidate`，保留 exact-key 校验并对最终 body 哈希。`apps/daemon/src/review-coordinator.ts:260-296` 与 `apps/daemon/src/review-coordinator.ts:389-402` 从无版本 body 派生 Review/Leader hash；`apps/daemon/src/recovery-manager.ts:196-395` 重算 semantic hash、验证 snapshot/Candidate binding，并保留 ArtifactRef、generation 和 publish CAS。`packages/publish/src/preflight.ts:72-85` 证明 `decisionHash` 未进入稳定 publish identity。

Fresh build 产物中没有 `schemaVersion`、`GitCandidateV3` 或 `document_schema_version`。相关 unit、integration、crash、recovery、publish-security、installed-package 测试以及 lint、typecheck、build、changeset check 均通过。
