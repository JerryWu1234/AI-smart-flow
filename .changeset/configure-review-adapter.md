Make daemon Review adapter selection strategy-driven and Host-aware, rename the former `daemon-codex` strategy to `codex`, add the `codex-desktop` strategy backed by a private Codex app-server process, remove `SMARTFLOW_CONFIG` YAML files and the daemon/doctor `--config` option, remove the redundant Codex version preflight, and rename the required Pi model environment variables to `BASE_URL`, `MODEL`, and `API_KEY`; the optional `API` setting defaults to `openai-responses`.

When `REVIEW_ADAPTER` is omitted, each new Job matches the MCP Host client name to a registered Review strategy and falls back to `codex` when the Host is missing or unrecognized. An explicit `REVIEW_ADAPTER` value of `codex`, `codex-desktop`, `claude-code`, `claude-code-desktop`, or `opencode` always wins. `REVIEW_MODEL` and `REVIEW_EFFORT` are passed through to the selected Reviewer; the Review deadline, retry budget, and no-progress threshold use fixed code defaults. The resolved adapter identity is stored with the Job so Review retries, repair rounds, daemon recovery, and cancellation cannot switch adapters. SmartFlow no longer reads `SMARTFLOW_CONFIG` or accepts daemon/doctor `--config`; existing YAML settings must migrate to the three `REVIEW_*` environment variables. The `codex` strategy uses `codex exec`, while `codex-desktop` starts `codex app-server --listen stdio://` for each create or resume call, uses read-only/no-approval turns, and never starts or controls the Desktop GUI. Unsupported app-server interaction requests fail the attempt instead of opening an approval UI. SmartFlow checks an explicitly selected Review adapter's executable before the MCP gateway or Daemon becomes ready; later authentication, provider, process, event, and output failures use the fixed retry and deadline budget before pausing rather than switching adapters. Launch environments must replace `SMARTFLOW_PI_API`, `SMARTFLOW_PI_BASE_URL`, `SMARTFLOW_PI_MODEL`, and `SMARTFLOW_PI_API_KEY` with the canonical `API`, `BASE_URL`, `MODEL`, and `API_KEY` names; MCP input may omit `API` to use `openai-responses`. The former names are rejected and have no compatibility aliases. MCP configurations must replace `SMARTFLOW_PI_THINKING` with `EFFORT`; `SMARTFLOW_PI_THINKING` is reserved for daemon-to-Worker transport. `SMARTFLOW_DATA_HOME`, `SMARTFLOW_PI_CONTEXT_WINDOW`, `SMARTFLOW_PI_MAX_TOKENS`, and `SMARTFLOW_PI_ATTEMPT_DEADLINE_MS` remain unchanged.
