Make daemon Review adapter selection strategy-driven and Host-aware, rename the former `daemon-codex` strategy to `codex`, add the `codex-desktop` strategy backed by a private Codex app-server process, remove the unused top-level configuration `version` and `review.onUnavailable` fields, remove the redundant Codex version preflight, and rename the required Pi model environment variables to `API`, `BASE_URL`, `MODEL`, and `API_KEY`.

When `review.strategy` is omitted, each new Job matches the MCP Host client name to a registered Review strategy and falls back to `codex` when the Host is missing or unrecognized. An explicit `codex` or `codex-desktop` value always wins. The resolved adapter identity is stored with the Job so Review retries, repair rounds, daemon recovery, and cancellation cannot switch adapters. Existing SmartFlow configuration files must remove `version` and `review.onUnavailable`; removed fields are rejected rather than ignored. The `codex` strategy uses `codex exec`, while `codex-desktop` starts `codex app-server --listen stdio://` for each create or resume call, uses read-only/no-approval turns, and never starts or controls the Desktop GUI. Unsupported app-server interaction requests fail the attempt instead of opening an approval UI. Daemon Review starts the real Agent call directly, and startup or execution failures use the existing `maxAttempts` and deadline budget before pausing rather than switching adapters. Launch environments must replace `SMARTFLOW_PI_API`, `SMARTFLOW_PI_BASE_URL`, `SMARTFLOW_PI_MODEL`, and `SMARTFLOW_PI_API_KEY` with the four new names; the former names are rejected and have no compatibility aliases. `SMARTFLOW_CONFIG`, `SMARTFLOW_DATA_HOME`, `SMARTFLOW_PI_CONTEXT_WINDOW`, `SMARTFLOW_PI_MAX_TOKENS`, `SMARTFLOW_PI_THINKING`, and `SMARTFLOW_PI_ATTEMPT_DEADLINE_MS` remain unchanged.
