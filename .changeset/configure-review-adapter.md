Make daemon Review adapter selection strategy-driven and Host-aware, rename the former `daemon-codex` strategy to `codex`, add the `codex-desktop` strategy backed by a private Codex app-server process, remove `SMARTFLOW_CONFIG` YAML files and the daemon/doctor `--config` option, and remove the redundant Codex version preflight.

When `REVIEW_ADAPTER` is omitted, each new Job matches the MCP Host client name to a registered Review strategy and falls back to `codex` when the Host is missing or unrecognized. An explicit `REVIEW_ADAPTER` value of `codex`, `codex-desktop`, `claude-code`, or `claude-code-desktop` always wins. `REVIEW_MODEL` and `REVIEW_EFFORT` are passed through to the selected Reviewer; the Review deadline, retry budget, and no-progress threshold use fixed code defaults. The resolved adapter identity is stored with the Job so Review retries, repair rounds, daemon recovery, and cancellation cannot switch adapters. SmartFlow no longer reads `SMARTFLOW_CONFIG` or accepts daemon/doctor `--config`; existing YAML settings must migrate to the three `REVIEW_*` environment variables. The `codex` strategy uses `codex exec`, while `codex-desktop` starts `codex app-server --listen stdio://` for each create or resume call, uses read-only/no-approval turns, and never starts or controls the Desktop GUI. Unsupported app-server interaction requests fail the attempt instead of opening an approval UI. Daemon Review starts the real Agent call directly, and startup or execution failures use the fixed retry and deadline budget before pausing rather than switching adapters. Worker model settings are configured through the `WORK_` environment namespace; see the separate `WORK_` namespace entry for the full list. `SMARTFLOW_DATA_HOME` remains unchanged.
